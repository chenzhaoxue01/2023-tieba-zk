# 百度贴吧设计文档

## 1. 项目概述

### 1.1 项目背景

基于Pixso设计理念，构建新一代社交化贴吧平台。随着移动互联网的深度发展，用户对社交功能的需求日益多元化。本项目将传统贴吧与现代化社交功能深度融合，打造集兴趣社区、位置服务、社交分享于一体的综合性平台。

**Pixso设计理念融合：**
- **协作设计思维**：支持多用户实时协作发帖、编辑
- **组件化设计**：模块化的UI组件库，支持快速迭代
- **交互体验优化**：流畅的动画过渡和手势操作
- **跨平台适配**：响应式设计支持多端体验

**市场机遇：**
- 兴趣社交+位置服务的蓝海市场
- 第三方服务集成的技术红利
- 智能化推荐算法的成熟应用
- 移动支付生态的完善支持

### 1.2 项目目标

**核心目标：**
- 构建社交化、智能化的贴吧生态系统
- 集成主流第三方服务（推送、地图、分享、登录）
- 实现基于位置的个性化内容推荐
- 打造跨平台的协作式社区体验

**技术目标：**
- 多端统一的推送服务架构
- 高精度地图服务集成
- 社交分享链路优化
- 第三方登录安全体系

**业务目标：**
- 日活跃用户达到200万
- 第三方登录用户占比60%
- 位置相关帖子占比30%
- 社交分享转化率提升50%

### 4.2 数据库设计

#### 用户表 (users)
```sql
CREATE TABLE users (
    id BIGSERIAL PRIMARY KEY,
    username VARCHAR(50) UNIQUE NOT NULL,
    email VARCHAR(100) UNIQUE,
    phone VARCHAR(20) UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    avatar_url VARCHAR(500),
    nickname VARCHAR(50),
    bio TEXT,
    level INTEGER DEFAULT 1,
    experience INTEGER DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    last_login TIMESTAMP,
    status SMALLINT DEFAULT 1
);
```

#### 贴吧表 (bars)
```sql
CREATE TABLE bars (
    id BIGSERIAL PRIMARY KEY,
    name VARCHAR(100) UNIQUE NOT NULL,
    description TEXT,
    avatar_url VARCHAR(500),
    background_url VARCHAR(500),
    category_id INTEGER,
    owner_id BIGINT REFERENCES users(id),
    member_count INTEGER DEFAULT 0,
    post_count INTEGER DEFAULT 0,
    today_post_count INTEGER DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    status SMALLINT DEFAULT 1,
    INDEX idx_category (category_id),
    INDEX idx_owner (owner_id)
);
```

#### 帖子表 (posts)
```sql
CREATE TABLE posts (
    id BIGSERIAL PRIMARY KEY,
    title VARCHAR(200) NOT NULL,
    content TEXT NOT NULL,
    author_id BIGINT REFERENCES users(id),
    bar_id BIGINT REFERENCES bars(id),
    type SMALLINT DEFAULT 1, -- 1:普通帖 2:精华帖 3:置顶帖
    view_count INTEGER DEFAULT 0,
    like_count INTEGER DEFAULT 0,
    comment_count INTEGER DEFAULT 0,
    share_count INTEGER DEFAULT 0,
    is_top BOOLEAN DEFAULT FALSE,
    is_essence BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    last_reply_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    status SMALLINT DEFAULT 1,
    INDEX idx_author (author_id),
    INDEX idx_bar (bar_id),
    INDEX idx_created (created_at),
    INDEX idx_hot (like_count, comment_count, created_at)
);
```

#### 评论表 (comments)
```sql
CREATE TABLE comments (
    id BIGSERIAL PRIMARY KEY,
    content TEXT NOT NULL,
    author_id BIGINT REFERENCES users(id),
    post_id BIGINT REFERENCES posts(id),
    parent_id BIGINT REFERENCES comments(id), -- 父评论ID
    like_count INTEGER DEFAULT 0,
    floor_number INTEGER, -- 楼层号
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    status SMALLINT DEFAULT 1,
    INDEX idx_post (post_id),
    INDEX idx_author (author_id),
    INDEX idx_parent (parent_id)
);
```

## 5. 产品原型设计

### 5.1 页面流程设计

#### 核心用户旅程（增强版）
1. **新用户注册流程**
   - 启动页 → 登录/注册页 → 第三方登录授权 → 选择兴趣贴吧 → 主页面
   - 支持手机号、邮箱、微信、QQ、微博等多种注册方式

2. **浏览帖子流程**
   - 主页面 → 贴吧列表 → 帖子列表 → 帖子详情 → 社交分享
   - 支持点赞、评论、收藏、分享到第三方平台

3. **发帖流程（含位置）**
   - 主页面 → 选择贴吧 → 发帖页面 → 获取当前位置 → 编辑内容 → 发布
   - 支持文字、图片、视频、位置签到等多种内容类型

4. **推送通知流程**
   - 系统推送 → 用户点击 → 跳转对应页面 → 交互操作
   - 支持WebPush、AppPush、短信、邮件多种推送方式

## 6. 技术选型深度分析

### 6.1 Veaury 技术选型深度分析

#### 技术选择: Veaury (Vue + React 混合框架)

**选择理由：**
1. **技术栈融合需求**：现有团队同时掌握Vue和React技术
2. **渐进式迁移**：支持从现有系统平滑过渡
3. **生态整合**：可同时使用Vue和React的丰富生态
4. **性能优化**：提供组件级优化和代码分割

#### 6.1.1 Veaury 框架核心优势

**零学习成本的混合开发：**
- Vue组件可直接在React项目中使用
- React组件可直接在Vue项目中使用
- 统一的开发体验和构建流程
- 共享状态管理和路由系统

**Veaury vs 传统混合方案对比：**

| 特性 | Veaury | 微前端 | iframe | 传统混合 |
|------|--------|--------|---------|----------|
| 开发体验 | 统一 | 隔离 | 完全隔离 | 割裂 |
| 性能 | 优秀 | 良好 | 较差 | 一般 |
| 组件复用 | 完全复用 | 有限复用 | 无法复用 | 部分复用 |
| 状态共享 | 无缝共享 | 有限共享 | 无法共享 | 困难 |
| 构建部署 | 统一构建 | 独立构建 | 独立部署 | 复杂 |

## 8. 风险评估与对策

### 8.1 技术风险

#### 前端技术风险
- **Veaury框架成熟度风险**：作为新兴框架，可能存在稳定性问题
- **Vue-React混合开发复杂度**：团队需要同时掌握两种技术栈
- **性能优化挑战**：混合框架可能带来额外的性能开销
- **第三方SDK集成风险**：不同SDK的兼容性和稳定性问题

#### 后端技术风险
- **Django并发性能**：高并发场景下可能遇到性能瓶颈
- **数据库扩展性**：PostgreSQL在大数据量下的扩展性挑战
- **微服务架构复杂度**：服务拆分带来的运维复杂性
- **第三方服务依赖风险**：外部API的稳定性和响应时间不可控

#### 第三方服务风险
- **API限制和配额**：第三方服务可能有调用频率限制
- **服务稳定性**：第三方服务宕机影响系统功能
- **数据安全**：第三方服务数据传输和存储安全风险
- **成本控制**：第三方服务使用成本可能超出预期

### 8.2 业务风险

#### 市场竞争风险
- **同类产品竞争**：贴吧类产品市场竞争激烈
- **用户获取成本**：新用户获取难度较大
- **内容监管风险**：UGC内容监管压力

#### 运营风险
- **内容质量管控**：用户生成内容质量难以保证
- **社区氛围维护**：需要投入大量人力进行社区管理
- **商业化变现**：盈利模式需要持续探索
- **第三方服务合规**：需要遵守各平台API使用规范

#### 用户体验风险
- **推送打扰**：过度推送可能导致用户流失
- **位置隐私**：位置功能可能引发用户隐私担忧
- **社交分享疲劳**：频繁的分享功能可能影响用户体验

### 8.3 应对策略

#### 技术风险应对
- 建立完善的技术选型评估机制
- 加强团队技术培训和技术储备
- 实施渐进式架构演进策略
